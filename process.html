VERSION NUMBERING

Format: MAJOR.MINOR.PATCH

MAJOR (3.x.x)Architecture overhaul, breaking change to save format or MP protocol
MINOR (x.1.x)New feature, new game mode, new weapon, new CFG section
PATCH (x.x.1)Bug fix, CFG tweak, slider adjustment, visual polish

Current: v4.1.0 — next patch v4.1.1 for bug fixes; next minor v4.2.0 for new features. Release notes: CHANGELOG.md

STANDARD EDIT WORKFLOW

Every change, no matter how small, follows this sequence:

1Make the change in the relevant split file(s) under js/, css/, or index.html.
2Test in the browser by opening index.html via a local server (npx serve . or equivalent).
3Apply the same change to the current versioned .html file (e.g. snake2048_v3.1.1.html). Use targeted find/replace — do not re-inline everything.
4Decide on a version bump (patch / minor / major) and pick the new version string.
5Save a new versioned file: copy the current .html, rename to the new version, bump the two version strings inside it (see below).
6Before adding any new const / let / top-level function: grep all other JS files for that name to catch duplicate declarations. A duplicate const kills the entire second file silently — the MISSING GLOBALS panel is the tell.
7If the change adds new CFG values or changes architecture: update schematic.html.
8If the change reveals a non-obvious pattern or pitfall: add an entry to lessons-learned.html.

VERSION BUMP CHECKLIST

Two places to update inside the versioned .html file:

1. HTML <title> tag (line ~9)

<title>Felix's Snake Cubes v3.1.1</title>

2. JS version comment (line ~395 inside <script>)

//  FELIX'S SNAKE CUBES — v3.1.1

Both must match the filename. The JS comment is what appears in the console / schematic.

Save command (using the terminal or Claude)

# Copy current version to new version number
cp snake2048_v3.1.0.html snake2048_v3.1.1.html
# Then edit the two version strings inside the new file

ADDING A NEW CFG VALUE

1Add the constant to js/config.js inside const CFG = { … } with a comment.
2Wire it up wherever the value is consumed (game-core, render, etc.).
3If it should be user-controllable: add a slider row to the settings panel HTML in index.html, and a handler in js/settings.js.
4Add the same three things to the versioned .html file (CFG entry + consumer + slider/handler).
5Add a row to the CFG table in schematic.html.
If the value feeds into a segment val (size, merging), it MUST be a power of 2. Use an exponent-based slider — see applyStartValSlider() in settings.js as the pattern.

ADDING A NEW SLIDER TO THE SETTINGS PANEL

HTML — add a row inside the template literal in the buildSettingsPanel IIFE (js/settings.js top AND in versioned .html)

// inside the sp.innerHTML = ` ... ` template in settings.js:
<div style="font-size:0.48rem;color:#444;text-transform:uppercase;
  letter-spacing:1px;margin-bottom:-4px;margin-top:2px">Section Name</div>
<div class="sp-row"><label>Label</label>
  <input class="sp-slider" id="myval-slider" type="range"
    min="1" max="10" value="5" step="1" style="--pct:44%">
  <span class="sp-val" id="myval-val">5</span></div>

JS handler (in js/settings.js AND in the versioned .html)

const _myvalSlider = document.getElementById('myval-slider');
const _myvalVal    = document.getElementById('myval-val');
function applyMyValSlider(v) {
  CFG.MY_VALUE = v;
  _myvalVal.textContent = v;
  const pct = Math.round((v - MIN) / (MAX - MIN) * 100);
  _myvalSlider.style.setProperty('--pct', pct + '%');
  _myvalSlider.value = v;
}
_myvalSlider.addEventListener('input', () => applyMyValSlider(parseInt(_myvalSlider.value)));
applyMyValSlider(5); // startup default

Startup value: pass the CFG value instead of a literal, e.g. applyMyValSlider(CFG.MY_VALUE). A hardcoded default makes the panel lie about the game (lessons-learned #22). For a scaled value, convert first, e.g. Math.round(CFG.BOT_SPEED * 100).
