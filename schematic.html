FELIX'S SNAKE CUBES — ARCHITECTURE SCHEMATIC

Refactored from monolithic snake2048_v3.0.1.html (5226 lines) into modular files. All JS uses plain <script> tags sharing a single global scope — NOT ES modules.

SCRIPT LOAD ORDER

Order is critical — later files reference globals defined earlier.

1. config.js       — CFG, WORLD_DENSITY, color helpers, VALS, BOT_PAL …
2. render.js       — canvas, ctx, W, H, CAM, project3, drawCube3, lerpAngle …
3. game-core.js    — G, newSnake, initGame, stepSnake, botTick, showFlash …
4. input.js        — TURN_SPEED, steerPlayer, triggerBurst, joystick handlers
5. weapons.js      — fireHook, tickHooks, fireTailBullet, drawActionCooldowns …
6. athena.js       — ATHENA object, startAthena, drawAthenaBoundary …
7. multiplayer.js  — MP object, initMPOverlay, broadcastState, mpOnKill …
8. settings.js     — slider wiring, initial G = {}, requestAnimationFrame(loop)
9. main.js         — loop(), draw(), lerpSeg(), drawRadar()
10. dad.js         — DAD object, startDad(), DAD.draw() — parallel render path  [PLANNED]

Note: settings.js calls requestAnimationFrame(loop) — loop() is defined in main.js which is loaded AFTER settings.js. This works because rAF fires asynchronously after all scripts are parsed.

dad.js loads last so that dadTerrainH() and drawDadObjects() are available when main.js and render.js call them at runtime. Guards in those files use typeof DAD — same pattern as ATHENA.

ATHENA GUARDS

athena.js loads 6th. Files 1–5 must guard ATHENA references with typeof checks:

// Pattern used throughout config.js, render.js, game-core.js, weapons.js:
if(typeof ATHENA !== 'undefined' && ATHENA.active) { … }

DAD'S MODE — PLANNED v3.2.0

A neighborhood/suburban world. Ground layer is a real satellite image (e.g. walteria.png) projected onto a 3D perspective plane via a secondary WebGL canvas. Snake logic, game tick, weapons, and MP are unchanged. Objects (trees, buildings, roads) are defined per-map in a JSON file produced by map-builder.html.

Rendering architecture

Two canvases, stacked:
  <canvas id="dad-bg">   — WebGL, z-index below main canvas
                            draws the satellite image as a perspective-projected
                            ground plane, scrolling with the camera (CAM)
  <canvas id="c">        — existing 2D canvas, transparent background in dad mode
                            draws snake, food, HUD, weapons on top

dad.js manages the WebGL canvas (init, resize, draw each frame).
main.js checks DAD.active and calls DAD.drawBg(now) before the 2D draw pass.
The 2D ground tile draw loop is skipped when DAD.active (image replaces it).

Map system — JSON per tile

assets/
  walteria.png          ← satellite image (any size)
  walteria.json         ← produced by map-builder.html
  future-map.png / .json

walteria.json schema:
{
  "id": "walteria",
  "image": "assets/walteria.png",
  "carPixels": 20,          ← image pixels per grid cell (= snake ≈ 1 car wide)
  "imageWidth": 512,
  "imageHeight": 512,
  "gridCols": 26,           ← Math.round(imageWidth / carPixels)
  "gridRows": 26,
  "objects": [
    { "type": "tree",     "x": 245, "y": 312 },
    { "type": "building", "pts": [[100,200],[200,200],[200,300],[100,300]] },
    { "type": "road",     "pts": [[0,150],[500,150]], "width": 14 }
  ]
}

Coordinates: image pixels (natural image dimensions).
dad.js normalizes to grid cells on load: gridX = imageX / carPixels.

Collision rules

Map edge      → snake bounces (direction reverses / deflects)
Building wall → snake bounces (same rule as map edge)
No wrap. No Athena-style shrink boundary.

Snake scale

CFG_DAD.CAR_PIXELS  — image pixels per grid cell (matches carPixels in JSON)
                      adjustable slider in settings; controls how large snakes
                      appear relative to the satellite image.
One grid cell ≈ one small vehicle width on the satellite image.

Multiple maps

DAD.maps = ['assets/walteria.json', …]   — list of available maps
DAD.currentMap = 0                        — index
loadDadMap(jsonPath)                      — fetch JSON, load image, rebuild grid
Maps are swappable at runtime; grid dimensions (A×B) change per map.

What changes in existing files

index.html     — add <canvas id="dad-bg"> behind #c; add <script src="js/dad.js">
render.js      — terrainH(): return 0 (flat) when DAD.active (image is the terrain)
main.js        — draw(): skip ground tile loop + call DAD.drawBg(now) when DAD.active
multiplayer.js — add "Dad's Mode" button → loadDadMap() then startDad()

DAD GUARDS pattern

// render.js terrainH():
if (typeof DAD !== 'undefined' && DAD.active) return 0;

// main.js draw() — before ground tile loop:
if (typeof DAD !== 'undefined' && DAD.active) { DAD.drawBg(now); }
else { /* existing ground tile loop */ }

map-builder.html

Standalone tool (no server needed). Opens assets/walteria.png flat (2D, no projection).
Tools: SELECT | TREE (click) | BUILDING (polygon, dbl-click/right-click to close)
       ROAD (polyline) | ERASE
Features: scroll-to-zoom, space+drag pan, grid overlay (carPixels), undo (Ctrl+Z),
          load/save JSON, load any image (drag-in or file picker).
Exports: <mapId>.json (download) — load into dad.js via loadDadMap().
Shortcuts: S=select T=tree B=building R=road E=erase Del=delete Esc=cancel
