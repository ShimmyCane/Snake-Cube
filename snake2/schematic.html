SNAKE II — ROMAN NUMERAL SNAKE · MVP SCHEMATIC

Status: plan only, nothing built yet. Items marked ASK are open questions for you; the plan uses the default shown until you answer. Lives in snake2/, separate from Felix's Snake Cubes.

1. THE IDEA IN ONE PARAGRAPH

A classic 2-D grid snake on a tight, walled field. Your snake is a number, written in Roman numerals, one symbol per body segment. Eat I snacks to count up. When the body spells something Romans would not write, it collapses: IIII snaps into IV and your tail gets shorter. Because a snake's length is the length of its numeral, every snack is a small puzzle: eating one more can make you longer or much shorter. Everyone moves at the same speed, on the grid, in four directions. One mode, three minutes, cartoon look.

2. THE CORE MECHANIC — THE BODY SPELLS THE NUMBER

 value 3        value 4             value 8            value 9         value 10
 [I][I][I]  +I  [I][V]        ...   [V][I][I][I]  +I   [I][X]    +I    [X]
 3 long         2 long  ← collapse  4 long             2 long          1 long

 head ─────────────────▶ tail       the head carries the first symbol;
                                    new symbols grow from the tail end

The snake never stores segments as values. It stores one integer, value. The body is always toRoman(value), one symbol per cell. When the value changes:

Numeral gets…What happens on the field
longerClassic growth: the tail stays put for one tick per extra symbol, so the body grows out of the tail.
shorterCollapse: the extra tail cells drop off at once, with a "IIII → IV!" pop so kids see the rewrite.
same lengthThe symbols just relabel (IV + V = IX).

Why it is a puzzle (lengths are real, computed)

ValueNumeralLengthLesson
3 → 4III → IV3 → 2Eating makes you shorter
8 → 9 → 10VIII → IX → X4 → 2 → 1Two snacks and you are a single tile
38 → 39 → 40XXXVIII → XXXIX → XL7 → 5 → 2Escape a tight spot by counting to 40
88 → 90LXXXVIII → XC8 → 2The longest snakes are one away from tiny
1888MDCCCLXXXVIII13Longest numeral up to the cap
2026MMXXVI6The cap — this year

Romans had no zero, so a snake starts at I and can never be 0. That is a nice fact for kids, and it gives a clean rule: you cannot shrink below I.

6. DATA MODEL

G2 = {
  state:     'menu' | 'countdown' | 'playing' | 'paused' | 'over' | 'won',
  timeLeftMs: 180000,
  tickAt:    performance.now() of the last step   (for smooth in-between drawing)
  snakes:    [player, bot1, bot2, bot3],
  player:    snakes[0],
  snacks:    [{ c, r, value }],            // value is 1, 5 or 10
  pops:      [{ c, r, text, at }],          // "IIII → IV!" floating labels
  best:      highest value reached this round
}

snake = {
  name, isPlayer, colour,
  value:     1,                             // the only source of truth
  cells:     [{c,r}, …]   head first        // length catches up to the numeral
  dir:       {dc, dr},  nextDir: {dc, dr},
  pendingGrow: 0,                           // tail cells still to grow
  alive, respawnAt, lives (player only)
}

symbols(snake) = toRoman(snake.value).split('')   // drawn onto cells[0..]

Invariant: after each tick, cells.length + pendingGrow === romanLength(value). The snake tests check this after every move.

7. ONE TICK (every 170 ms, all snakes together)

1. Directions   player: nextDir from input (ignore reversal) · bots: botChooseDir()
2. Targets      each live snake's new head cell = head + dir
3. Resolve      wall            → crash
                own body        → crash (except the cell the tail leaves this tick)
                another snake   → bigger value eats the smaller whole; smaller crashes; equal: both crash
4. Move         unshift new head; pop the tail unless pendingGrow > 0 (then pendingGrow--)
5. Eat snack    value += snack.value (capped at 2026); spawn a replacement snack
6. Rewrite      newLen = romanLength(value)
                  newLen > cells → pendingGrow += difference
                  newLen < cells → drop tail cells now, add a pop "old → new"
7. Check        player value == 2026 → 'won' · lives == 0 → 'over' · timer == 0 → 'over'

All snakes move in one step, so nobody gets a head start from list order. Head-on collisions are decided on the new cells in step 3.

11. BOTS

botChooseDir(bot):
  safe = the 3 non-reversing moves that do not hit a wall, a body, or a cell
         a bigger snake's head could reach next tick
  if a smaller snake's head is within 4 cells → step toward it (hunt)      [stretch]
  else → BFS on the grid to the nearest snack; take the first step
  no path → any safe move; no safe move → keep going (it will crash)

BFS on 18 × 24 = 432 cells is cheap enough to run for every bot on every tick.
